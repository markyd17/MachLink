# MachLink

A locally-hosted companion app for DCS World and MSFS 2024. It detects the
aircraft you're flying, shows startup/shutdown/weapons/flight-planning
reference material for that specific airframe, pulls your SimBrief flight
plan, and lets you ask follow-up questions — grounded only in the reference
data you've loaded, not free-generated by an LLM.

## Why it's built this way (read this first)

You asked for zero hallucinations and procedures that are actually correct
for the active airframe. The only reliable way to get that is: **the app
never invents procedures.** All checklist/weapons/systems content comes from
structured JSON files you build from real sources (Chuck's Guides for DCS,
JayDee's Checklists for MSFS). The app's job is to detect context, retrieve
the matching content, and display/search it — not to generate it.

Because Chuck's Guides and JayDee's Checklists are copyrighted by their
authors (free to download, not licensed for me to bulk-copy into this repo),
this project ships with an **empty data set** and a **PDF import tool** that
extracts text from PDFs *you* own into an editable draft, which you then
review and save as structured JSON. That review step is what actually
guarantees accuracy — a human (you) checks it once per airframe, then it's
correct forever, instead of an LLM re-deriving it every time and occasionally
getting a switch order wrong.

An optional "Ask" free-text box exists for questions not covered by your
loaded data. It is clearly labeled when it's answering from an LLM instead
of your sourced data, so you always know which kind of answer you're
getting.

## What's included

- `app.py` — local Flask server + web UI, opened as its own native app window via `pywebview` (falls back to a browser tab if that's not installed)
- `integrations/dcs_export_hook.lua` — drop-in addition to DCS's Export.lua that reports the active aircraft, plus altitude/velocity telemetry for the Debrief feature below
- `integrations/dcs_listener.py` — receives that report over localhost UDP
- `integrations/dcs_hook_guard.py` — keeps the hook above actually present in the live Export.lua, re-adding it if another tool overwrites the file
- `integrations/dcs_flight_tracker.py` — the Debrief feature's flight state machine (landing/crash detection, the 5-minute minimum, the finished-flight log)
- `integrations/dcs_mission_hook.lua` + `integrations/dcs_combat_events.py` — Phase 2 of Debrief: real combat events (shot down vs. crashed vs. ejected, by what/whom), via a watched file rather than a socket — see "Debrief" below, this one needs an extra one-time setup step
- `integrations/dcs_mission_briefing.py` — reads the real in-mission briefing (sortie/tasking) for the active DCS mission
- `integrations/dcs_kneeboard.py` — surfaces each aircraft's real static kneeboard reference pages
- `integrations/msfs_watcher.py` — polls MSFS via SimConnect for the active aircraft
- `integrations/simbrief.py` — pulls your latest OFP from SimBrief by username/Pilot ID
- `tools/pdf_import.py` — extracts raw text from a checklist PDF you own, for you to curate into JSON
- `data/aircraft/_TEMPLATE.json` — the schema every airframe file follows
- `data/aircraft/_SAMPLE_PLACEHOLDER.json` — a fake, clearly-marked example so you can see the format working end to end. **Do not fly from this file — it is not real data.**

## Setup (on your gaming PC, not in this chat)

1. Install Python 3.10+ if you don't have it.
2. Unzip this project anywhere, e.g. `C:\MachLink`.
3. Open a terminal in that folder and run:
   ```
   pip install -r requirements.txt
   ```
4. Copy `config.example.yaml` to `config.yaml` and fill in:
   - your SimBrief username or Pilot ID
   - (optional) an Anthropic API key, only needed if you want the free-text "Ask" fallback for things not in your loaded data
5. Start it:
   - Windows: double-click `run.bat`
   - Mac/Linux: `./run.sh`
6. MachLink opens in its own app window automatically (via `pywebview` -
   no browser tab needed). If `pywebview` isn't installed, it falls back
   to opening http://localhost:5000 in your default browser instead. Leave
   the console window running in the background while you fly either way.

## Wiring up the game hooks

### DCS
Open your DCS `Scripts/Export.lua` (in Saved Games, not the install dir —
create the file if it doesn't exist) and append the contents of
`integrations/dcs_export_hook.lua`. This makes DCS send a tiny UDP message
to the app whenever the mission (re)loads, reporting your active module.

**Note if you also run a HOTAS/panel configurator (e.g. WinWing's SimApp
Pro):** those tools manage `Export.lua` too, and some of them overwrite the
whole file - wiping out our hook - on their own updates, on their "repair"
features, or even on their own startup. If a compatible tool is detected
doing this, check its settings for an option to stop it auto-writing
`Export.lua` (SimApp Pro calls this something like "close the modification
of Export.lua"). Either way, MachLink no longer depends on that:
`integrations/dcs_hook_guard.py` checks `Export.lua` for our hook every time
the app starts and every `dcs.hook_check_interval_seconds` (60s by default)
while it's running, and silently re-adds the hook if something else removed
it - printing a note in the console when it has to. It never touches
anything else already in the file, and keeps a one-deep backup at
`Export.lua.machlink_backup` from just before the last repair.

### MSFS 2024
`integrations/msfs_watcher.py` uses SimConnect and needs MSFS running with
SimConnect enabled (default). Nothing to configure in-sim — just have MSFS
open before you check status in the app.

## Debrief (after-action report)

The **GENERATE DEBRIEF** button lights up lime green once MachLink detects
you've landed and stopped after flying more than 5 minutes, and shows total
time, airborne time, takeoffs/landings, and — if the flight ended in a
loss — whether it was a crash or a shoot-down, and by what/whom.

**Phase 1 (automatic, no extra setup):** works off the same `Export.lua`
hook above (aircraft height/velocity). Detects landings normally, and
detects a destroyed aircraft by a timeout — DCS stops reporting export data
the instant your aircraft is destroyed, so ~10 seconds of telemetry silence
while airborne is read as a crash. This always works once the DCS hook
above is installed, but can't say *what* destroyed you.

**Phase 2 (real shoot-down/crash/ejection detection, one extra one-time
step):** adds `integrations/dcs_mission_hook.lua`, which runs in DCS's
Mission Scripting environment and reports actual combat events — who/what
shot you down, whether it was a friendly or enemy aircraft or ground unit,
the weapon used, and whether you ejected — plus correctly handles
respawning into a new life (even the same airframe type) without needing to
quit the mission. Getting there requires DCS's Mission Scripting sandbox to
be loosened, since by default it can't run much of anything useful for
getting data out:

1. Copy `integrations/dcs_mission_hook.lua` to
   `Saved Games\DCS\Scripts\MachLinkMissionHook.lua`.
2. Back up `<your DCS install>\Scripts\MissionScripting.lua`, then edit it:
   comment out the `sanitizeModule`/`require`/`loadlib`/`package` block
   (the file's own comments already say this is a supported customization
   point), and add a few lines to `dofile()` the hook above if it's
   present. See the `MACHLINK_MISSION_HOOK` marker comment for the exact
   block — this step needs an elevated (Administrator) terminal, since
   Windows protects `Program Files` from normal write access. **Write the
   file as plain ASCII/UTF-8 *without* a BOM** — `Set-Content -Encoding
   utf8` in Windows PowerShell adds one silently, which breaks Lua parsing
   and (since this file runs before every mission) stops every mission
   from loading at all until fixed. `Set-Content -Encoding ascii` avoids
   this.
3. MachLink then watches `Saved Games\DCS\Scripts\MachLinkCombatEvents.jsonl`
   for events. **Note:** the hook reports events by *appending JSON lines
   to that file*, not over a UDP socket like Export.lua's hook — confirmed
   empirically that `require("socket")` does not work inside DCS's Mission
   Scripting environment even with the sandbox loosened (dcs.log: `load
   error ... error loading module 'socket'`); only Export.lua's separate
   environment supports real sockets. `io.open`/`write`/`close` are plain
   built-in Lua, unaffected by that limitation, so that's what this hook
   uses instead.

**Worth knowing:** step 2 loosens DCS's sandbox for *every* mission you
fly, not just your own (a mission from a server or a friend could use the
same unlocked functions) — a common tradeoff for this kind of tool (MOOSE
and similar mission-scripting frameworks require the same edit), but a real
one. It also lives in DCS's install directory, so a DCS update can silently
revert it — Phase 1 above is unaffected either way, so Debrief keeps
working (just without shoot-down detail) until Phase 2 is reinstalled. This
does **not** put you at risk with multiplayer integrity checks — those
check textures/3D models and `Saved Games\DCS\Mods\`, not `Export.lua` or
`MissionScripting.lua`, and this exact edit is the standard, widely-used
requirement for running MOOSE-based missions on public servers.

**Testing tip:** `dcs.debrief_min_flight_seconds` in `config.yaml` controls
how long a flight must be airborne before Debrief will generate a report -
300 (5 minutes) is the real spec, but lower it (e.g. 30) while actively
testing Debrief itself so you don't need a full 5-minute sortie every time.

## Building out your aircraft library

For each airframe:
1. Download the PDF from Chuck's Guides (DCS) or JayDee's Checklists (MSFS) — your own legally-downloaded copy.
2. Run: `python tools/pdf_import.py path/to/guide.pdf --out data/aircraft/draft_<name>.txt`
3. Open the draft, and manually copy the relevant startup/shutdown/weapons/systems text into a new file following `_TEMPLATE.json`'s structure. This is the one manual step — it's what keeps the data accurate.
4. Save it as `data/aircraft/<exact-in-sim-name>.json` — the detector matches on this filename, see NOTES in the template.

This is slower than "just generate it," on purpose. Once a file is built
it's reusable forever and never wrong.
